# specs

Per-feature/change specs, written before implementation. One markdown file per
spec, named for the feature (e.g. `2026-08-quota-caps.md`).

This is separate from `docs/`, which documents the system as it currently is
(`ROADMAP.md`, `ARCHITECTURE.md`, `DECISIONS.md`). A spec here proposes a
change; once it lands, update the relevant `docs/` file and/or `DECISIONS.md`
rather than treating the spec itself as living documentation.

No fixed template yet — until one emerges, cover at minimum:

- **Problem** — what's wrong or missing today
- **Approach** — the proposed change
- **Acceptance criteria** — how to tell it's done
